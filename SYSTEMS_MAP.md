# Systems map

This file exists so a reader can decide which small part of unfollow-garden is relevant to a task without opening anything else. Areas are divided by reason for change — parts that change for the same reason share an entry, even when they sit in different directories.

The application is pre-release: the process layer and the platform wiring are built, and the runtime areas below are the thin end of the wedge. `PRD.md` describes the module layout the five release slices grow into; this file describes what exists today.

## Areas

### Identity and OAuth configuration

For: Who this app says it is to every atproto authorization server, and exactly what it asks permission to do.
Lives at: `src/lib/atproto/client-config.ts`, `src/routes/oauth-client-metadata.json/+server.ts`
Why this shape: The scope string is defined once because the authorization server compares the scope requested against the scope in the metadata it fetched. Two literals that "obviously match" is how that pair drifts, and the resulting failure names neither file.
Seams: `OAUTH_SCOPE` is the single point where the app's permissions change — widening it is a product decision, not a wiring one. `buildClientMetadata(origin)` derives `client_id` and `redirect_uris` from the live request origin, which is the seam that makes the same code correct in dev and production.
Fragile: The metadata route can never be prerendered — it must know the origin serving it. `client_id` is a public URL that appears on the consent screen, so the production hostname is user-facing and still unsettled (`CONTEXT.md`). In dev the loopback client only works when the app is opened at `127.0.0.1`, not `localhost`.

### App shell and routes

For: The rendered product surface — pages, layout, and the document shell. Today a placeholder landing page; slice 1 replaces it with sign-in and triage.
Lives at: `src/routes/+layout.ts`, `src/routes/+layout.svelte`, `src/routes/+page.svelte`, `src/app.html`, `src/app.css`, `src/app.d.ts`
Why this shape: `+layout.ts` sets `ssr = false` for the whole app. Every screen reads from IndexedDB and the user's OAuth session, neither of which exists on a server — and rendering server-side would mean sending a server data the PRD says never leaves the browser.
Seams: `src/app.css` is the single global-style entry point (the stylebase import plus app-wide rules). `src/app.d.ts` types `App.Platform`.
Fragile: `ssr = false` is a project-wide invariant, not a per-route convenience — a route that re-enables it is a privacy regression, not a performance tweak.

### UI foundation

For: The design-system layer — primitives, their stories, and the token base they assume.
Lives at: `src/lib/components/ui/Button.svelte`, `src/lib/styles/`, `src/stories/`, `.storybook/`
Why this shape: Primitives and stories share an area because a primitive change is incomplete without its story update (`CLAUDE.md`, "Storybook discipline") — they change for the same reason by rule.
Seams: `@taurean/stylebase` is imported exactly once, in `src/app.css` — swap or extend the token base there. `.storybook/main.ts` globs stories from all of `src/`, so a story can sit beside its component or in `src/stories/`. `Button` wraps Bits UI's `Button.Root`; new primitives follow the same wrap-a-headless-primitive pattern.
Fragile: `Button`'s styles lean entirely on stylebase custom properties (`--hue-*`, `--space-*`, `--ff-ui`) and the `u:fs-1` utility class — removing stylebase leaves it unstyled with no build error. The PRD's timeline strip is the component with real visual complexity and does not exist yet; it will carry most of this area's weight.

### Platform, deploy, and content security

For: How the app becomes a Cloudflare Worker, and what the browser is allowed to talk to once it gets there.
Lives at: `wrangler.jsonc`, `svelte.config.js`, `worker-configuration.d.ts` (generated)
Why this shape: The deployment serves static assets plus one metadata route. There are no bindings because there is no server-side state — that follows from the PRD's no-server-storage goal, not from the app being small.
Seams: The adapter line in `svelte.config.js` is the swap point for leaving Cloudflare. Bindings added to `wrangler.jsonc` would flow into `Env` via `pnpm gen` and surface through `App.Platform` — but adding one re-opens a product decision.
Fragile: `connect-src` and `img-src` allow `https:` broadly, because subjects' PDSes are arbitrary hosts discovered at runtime. Narrowing them to known Bluesky hosts silently breaks every self-hosted account; the breakage appears as a per-subject load error, not a CSP report anyone reads. `worker-configuration.d.ts` is generated — `pnpm build` and `pnpm check` run `wrangler types --check` and fail when it drifts. `wrangler.jsonc`'s `main` points at build output, so `pnpm preview` needs a build first.

### Verification harness

For: What "passing" means for this repo — the test projects, lint, and formatting policy.
Lives at: `vite.config.ts` (the `test.projects` block), `eslint.config.js`, the scripts in `package.json`
Why this shape: One Vitest config carries three projects — browser `client`, node `server`, and `storybook` story tests — so a single `pnpm test` covers every seam the testing doctrine names (`.claude/skills/task/testing.md`). The `server` project is the home for the PRD's activity-metric tests, which are pure functions unit tested independently of any UI.
Seams: A new kind of test is a fourth entry in `test.projects`. File naming routes tests: `*.svelte.{test,spec}.ts` runs in the browser project, plain `*.{test,spec}.ts` in node.
Fragile: `eslint.config.js` builds its ignore list from `.gitignore` (`includeIgnoreFile`), so editing `.gitignore` silently changes what gets linted. Prettier checks everything, including `.claude/` markdown — process-layer edits can fail `pnpm lint`. `requireAssertions: true` means a test with no assertion fails.

### Process layer

For: How work happens in this repo — the rulebook, the task-process skills, the decision graph, and release conventions; independent of what the app does.
Lives at: `CLAUDE.md`, `.claude/skills/` (`task` is the spine; `project-plan`, `review`, `writing-css`, `design` support it), `.claude/commands/`, `.claude/hooks/`, `.deciduous/`
Why this shape: Inherited from suede at `2026.7.3.3` and tailored at kickoff. The project standardized on Claude — the `.pi/` layer and `AGENTS.md` were dropped rather than maintained in parallel, because a second copy of the process rules rots the moment someone edits only one.
Seams: `deciduous update` owns `.claude/commands/`, `.claude/hooks/`, and its own section of `CLAUDE.md`; it preserves custom content, so house conventions sit alongside the generated block rather than replacing it.
Fragile: `.deciduous/` is per-machine (only `sync/` is committable), so the graph does not travel with a clone. `docs/` is the regenerated graph viewer — gitignored; never edit by hand. A pre-edit hook blocks edits unless a goal or action node was logged recently, so real-time graph logging is enforced rather than encouraged.
